# Coolify

Coolify runs the same `docker-compose.yml`. Two things to know.

## Let Coolify terminate TLS

Coolify's Traefik handles certificates and proxies to the `nginx` service in the stack. **Don't add a second TLS layer.**

1. **New Resource → Docker Compose**, pointed at the repository.
2. Set the domain on the **`nginx`** service. nginx listens on container port **80**, so the domain should usually be just `https://prints.example.com` with no port suffix. *Not* on `web`: `web` doesn't serve files, and pointing at it directly loses the `X-Accel-Redirect` hand-off that keeps large downloads off the Node event loop.
3. Add the environment variables from [Docker Compose](/deploy/docker-compose#setup) under **Environment Variables**. `APP_URL` and `BETTER_AUTH_URL` must be the public `https://` address, or share links and slicer hand-off will be built with the wrong host.

Don't use `docker-compose.local.yml` on Coolify. It publishes a fixed host port, and Traefik reaches nginx internally instead.

## Storage must be a persistent volume

In Coolify's **Storages** tab, mount:

| Path in container | Holds | If you lose it |
| --- | --- | --- |
| `/data/library` | Your model files (or bind-mount an existing folder) | The models themselves |
| `/data/previews` | Generated thumbnails | Nothing, regenerated by a scan |
| `/var/lib/postgresql` | The database | Metadata, unless you have sidecars or a backup |

::: warning Postgres 18 changed its data directory
Mount `/var/lib/postgresql`, **not** `/var/lib/postgresql/data`. The container refuses to start with the older convention.
:::

## Library mounts and the Coolify volume parser

The library mounts use **long YAML syntax** so Coolify can parse the host path and the read-only setting independently:

```yaml
- type: bind
  source: ${LIBRARY_PATH:-./libraries}
  target: /libraries
  read_only: ${LIBRARY_READ_ONLY:-true}
```

If an older 0.5.0 compose file fails with:

```text
Invalid volume source: contains forbidden character '${'
```

replace the short library mount entries with the long-form entries in the current compose file. Changing `LIBRARY_PATH` in Environment Variables alone does not fix the parser error. Keep the same host path and persistent volumes when redeploying, and load the updated compose file in Coolify before redeploying. This was fixed in [v0.5.1](/releases/v0.5.1).

## Network storage

A NAS share is just a path. Mount it on the host and point `LIBRARY_PATH` at it. See [Storage & NAS Mounts](/deploy/storage).

## Upgrading on Coolify

Load the updated compose file, keep your existing `LIBRARY_PATH`, database volume and data volume, and redeploy. Take a database backup first. See [Upgrading](/deploy/upgrading).
